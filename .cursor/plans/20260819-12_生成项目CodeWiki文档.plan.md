# 生成项目 Code Wiki 文档

## 背景 / 目标

Alpha 项目目前已有 README.md 描述产品功能与使用方法，但缺少一份面向**开发者/维护者**的深度 Code Wiki 文档。现有新贡献者/维护者需要通读代码才能理解：
- 各模块的输入输出与调用关系
- 核心数据结构与状态流转
- 后台调度循环之间的协同机制
- 新增策略/规则/接口的标准扩展方式
- 数据库 schema 与表用途
- 前端 JS 代码的路由与渲染机制

**目标**：生成一份完整的 Code Wiki（Markdown 格式），涵盖架构总览、模块详解、数据流、数据库设计、前端架构、扩展开发指南、调试运维、常见问题等章节，帮助开发者快速理解与二次开发。

## 验收标准

1. **完整性**：覆盖 T3 中全部 17 个文件，每个核心模块至少 1 个章节。
2. **准确性**：所有函数名、类名、表名、参数、文件路径与实际代码完全一致，引用带行号链接。
3. **可操作性**：扩展开发指南中的"新增原子规则 / 新增策略 / 新增路由"可按步骤实际执行成功。
4. **可导航性**：Code Wiki 目录索引页包含全部章节链接，README.md 可跳转到 Wiki。
5. **不重复**：Code Wiki 聚焦"代码如何实现"，不重复 README 中的产品功能描述；重复内容以 README 为准并交叉引用。

## 风险与回滚

| 风险 | 应对 |
|------|------|
| Code Wiki 文件过多（17 个）导致单轮生成过长 | 分批写入，使用 general_purpose_task 子 agent 并行生成章节 |
| 代码细节记忆偏差导致文档不准确 | 每写一个章节前先 Read 对应源码，核对类名/函数签名 |
| 生成的文档与 README 内容重复 | 先读 README，章节规划时明确分工：README 讲"做什么/怎么用"，Wiki 讲"怎么实现/怎么扩展" |
| 相对链接在不同平台失效 | 所有文件内部引用使用**绝对路径** `file:///workspace/...` 或 **同目录相对链接**，URL encode 空格/中文 |

## 关键决策记录

- **Wiki 存放位置**：`docs/code-wiki/` 目录（与 `docs/screenshots/`、`docs/hermes-agent-integration.md` 并列），避免污染项目根目录。
- **拆分粒度**：按"领域 + 深度"拆 17 个文件，单文件控制在 200~800 行以内；避免 1 个大文件难检索。
- **引用规范**：代码引用全部使用 `file:///workspace/绝对路径#L起始-L结束` 格式，确保 IDE 中可直接点击跳转。
- **与 README 的分工**：README = 产品文档（功能、截图、快速开始、API 列表）；Code Wiki = 开发文档（实现原理、模块关系、扩展方式、调试）。
